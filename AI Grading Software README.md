The platform grades student work automatically and lets examiners review the result. A student uploads a submission that an examiner reviews. A submission moves from `UPLOADED` to `AI_GRADED` and ends `REVIEWED` or `REJECTED`. Once it is reviewed, the examiner records rubric scores with the feedback generated for each criterion.

## Tech stack
Java 21, Spring Boot 4.1.1, PostgreSQL, Maven.

## Domain model
| Entity | Table | Notes |
| `Discipline` | `discipline` | many-to-many with `Examiner` |
| `Course` | `course` | knows nothing about its examiner |
| `Examiner` | `examiner` | `@ManyToOne Course` (nullable), owns the many-to-many `examiner_discipline` |
| `Student` | `student` | `studentNumber` is unique (business key) |
| `Submission` | `submission` | `@ManyToOne Student`, `@ManyToOne Examiner`, `SubmissionStatus` stored as text |
| `RubricScore` | `rubric_score` | `@ManyToOne Submission`, written only for `REVIEWED` submissions |

All ids are UUIDs generated by JPA.

## How to run the API

### Prerequisites

- JDK 21
- Maven 3.9+
- PostgreSQL

### 2. Create the database
Create the database then...
The tables are created automatically at startup (`spring.jpa.hibernate.ddl-auto=update`).

### 3. Configure the connection

"application properties" reads the credentials from environment variables:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/grading_db
spring.datasource.username=${DB_USERNAME:orlandoishimwe}
spring.datasource.password=${DB_PASSWORD:}
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
```

```bash
export DB_USERNAME=postgres
export DB_PASSWORD=your_password
```

### 4. Start the API

```bash
mvn clean spring-boot:run
```

The API listens on `http://localhost:8080`. A healthy start ends with `Started AiGradingApplication` and shows the `create table ...` statements in the console on the first run.

### 5. Test with Postman

Import the json file in postman...
Open the collection and click **Run collection**. Keep the order as it is.

The first folder enters the seed data through the save endpoints and stores every id in collection variables. Each request has test scripts that check the status code, the exact message and the returned data. Dates are computed relative to today, because a submission date in the past is refused.

### Status flow

| Current status | Allowed new status |
|---|---|
| `UPLOADED` | `AI_GRADED` or `REJECTED` |
| `AI_GRADED` | `REVIEWED` or `REJECTED` |
| `REVIEWED`, `REJECTED` | none (final) |
